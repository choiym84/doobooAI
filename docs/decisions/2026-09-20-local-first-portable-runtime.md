# 로컬 우선, 이식 가능한 런타임

- 상태: 승인
- 날짜: 2026-09-20

## 맥락

초기 개발·테스트는 개인 컴퓨터에서 진행한다. 그러나 Discord 알림은 장기적으로 항상 실행되는 서버에서 동작해야 하므로, 로컬 구현이 특정 컴퓨터나 서비스에 고정되면 안 된다.

## 결정

- 앱은 Node.js/TypeScript 단일 프로세스로 시작한다.
- 로컬 DB는 Docker Compose의 PostgreSQL을 사용한다. SQLite나 인메모리 DB를 운영 데이터 모델로 사용하지 않는다.
- DB 접속 정보, 봇 토큰, AI 공급자·모델·키는 환경 변수로만 주입한다.
- 앱은 컨테이너 이미지로 빌드할 수 있게 `Dockerfile`을 유지한다.
- 로컬과 서버의 차이는 `DATABASE_URL`과 비밀값, 실행 환경뿐이다. 도메인 코드나 마이그레이션은 공유한다.

## 이유와 대안

PostgreSQL을 처음부터 사용하면 알림 이력, 시간대, 트랜잭션, 운영 DB 이관에서 발생하는 차이를 줄일 수 있다. Docker Compose는 로컬 설치 부담을 낮추되 데이터는 `data/postgres`에만 보존한다.

## 이관 절차

1. 운영 PostgreSQL을 만들고 스키마 마이그레이션을 적용한다.
2. 운영 환경의 비밀 저장소에 `DATABASE_URL`, `DISCORD_BOT_TOKEN`, `GEMINI_API_KEY`를 등록한다.
3. 같은 Dockerfile로 이미지를 빌드·실행한다.
4. 헬스 체크, 발송 이력, 오류 로그를 확인한 뒤 로컬 프로세스를 중지한다.

이 단계에서 공급자·DB·Discord 도메인 코드를 다시 작성하지 않는다.
