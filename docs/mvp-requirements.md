# Discord 개인 AI 비서 MVP 요구사항

## 1. 목적

Discord 대화와 시간표 이미지를 통해 대학(원)생의 학기·수업·시험 일정을 관리하고, 적절한 시점에 먼저 알리는 개인 AI 비서를 만든다.

이 제품의 핵심은 대화형 챗봇이 아니라 **사용자의 학기 상태를 DB에 유지하고 자동화하는 일정 시스템**이다.

### 최우선 제품 원칙

1. **사용성 우선**: 사용자는 Discord에 자연어 또는 이미지를 보내는 것만으로 기능을 사용할 수 있어야 한다. 내부의 AI·DB·스케줄러 구조를 알 필요가 없어야 한다.
2. **자동화 우선**: 이미지에서 필요한 정보를 자동 추출하고, 검증된 일정 데이터를 바탕으로 정해진 시각에 알림을 자동 발송해야 한다.
3. **실패도 대화로 안내**: 해석 실패·권한 부족·외부 API 오류·예약 발송 실패를 조용히 삼키지 않고, 사용자가 다음에 무엇을 해야 하는지 Discord 메시지로 알려야 한다.

모든 기능은 다음의 완료 흐름을 기준으로 설계한다.

```text
Discord 입력(텍스트/이미지)
  → 자동 인식·구조화
  → 서버 검증 및 모호성 확인
  → DB 저장
  → 예약 작업 등록
  → 정해진 시각에 중복 없이 자동 발송
  → 처리 결과와 실패 원인을 Discord에 안내
```

## 2. 범위

### 확정 — MVP에 포함

1. Discord에서 시간표 이미지를 받아 과목명, 요일, 시작/종료 시각, 강의실을 추출한다.
2. 추출 결과를 사용자에게 보여주고, 사용자가 저장을 승인한 뒤에만 시간표를 저장한다.
3. 자연어로 학기 시작일·종강일, 시험 일정, 강의실, 휴강/보강 정보를 등록·수정·삭제한다.
4. 자연어로 오늘 일정, 이번 주 일정, 특정 과목 수업/시험 정보를 조회한다.
5. 기본값으로 수업 30분 전 알림과 시험 전 알림을 Discord로 발송한다.
6. 종강일 경과 시 활성 학기를 종료하고 해당 학기의 수업 리마인드를 중단한다.
7. 새 학기 등록 시 기존 활성 학기를 종료 또는 보관하고 새 학기의 시간표와 학기 정보를 받는다.

### 제외 — MVP 이후

- Notion 연동 및 수업 노트 기반 요약·복습 콘텐츠
- 공동 사용자, 공유 시간표, 권한 관리
- 웹 또는 모바일 설정 화면
- 장기 대화 기억을 이용한 일정 사실 관리
- 복잡한 반복 일정 및 학사 시스템 자동 동기화

## 3. 사용자 흐름과 수용 기준

### Discord 입력 채널

1. 사용자는 설정된 전용 텍스트 채널에 자연어 또는 이미지를 보내며, 봇을 멘션하지 않아도 된다.
2. 봇은 설정된 채널의 사람 메시지만 처리하고 다른 채널과 DM의 메시지는 무시한다.
3. 개인 일정이 다른 사용자에게 노출되거나 변경되지 않도록 채널 접근 권한은 사용자와 봇으로 제한한다.

### 시간표 이미지 등록

1. 사용자가 Discord에 시간표 이미지를 올린다.
2. 시스템은 구조화된 인식 결과를 제시한다.
3. 사용자는 저장, 수정, 취소 중 하나를 선택한다.
4. 저장 선택 전에는 Course/Schedule 데이터가 변경되지 않는다.
5. 수정·취소 시에도 사용자가 의도하지 않은 기존 일정이 변경되지 않는다.
6. 이미지 업로드 후 사용자가 별도 명령을 반복하지 않아도 인식·검증 결과가 자동으로 반환된다.
7. 이미지 품질이나 인식 결과가 불충분하면 저장하지 않고, 필요한 재촬영·추가 정보를 구체적으로 요청한다.

### 자연어 일정 변경

1. 시스템은 입력을 허용된 command와 스키마로 해석한다.
2. 대상 레코드가 하나로 식별되고 변경 내용이 명확하면 검증 후 적용한다.
3. 대상이 여럿이거나 날짜·시간·과목이 모호하거나 영향이 큰 경우, 변경안을 보여주고 확인을 받는다.
4. 결과 메시지는 적용·대기·실패 상태와 그 이유를 분명히 알린다.

### 자동 알림

1. 수업 시작 30분 전에 해당 수업의 시간·강의실을 알린다.
2. 휴강 수업은 알리지 않는다.
3. 활성 학기가 아니면 수업 리마인드를 보내지 않는다.
4. 동일 알림은 재시도 상황에서도 한 번만 사용자에게 전달된다.
5. 시험 알림의 리드 타임은 사용자 설정을 지원할 수 있도록 설계한다.
6. 예약 작업은 프로세스 재시작 후에도 복구되어야 한다.
7. 발송 실패는 재시도하고, 최종 실패 시 사용자에게 상태를 알리며 이력을 남긴다.

## 4. 데이터 원칙

- 비정형 입력(메시지, 이미지) → AI 구조화 출력 → 검증 → DB 저장 순서를 따른다.
- `User`, `Semester`, `Course` 또는 `CourseSchedule`, `Exam`, `ScheduleException`, `NotificationPreference`를 최소 도메인으로 둔다.
- 실제 발송 결과를 기록하는 NotificationDelivery(명칭은 구현 단계에서 조정 가능)를 둔다.
- Semester 상태는 최소 `PLANNED`, `ACTIVE`, `COMPLETED`, `ARCHIVED`를 지원한다.
- 일회성 일정 변경은 원본 시간표를 덮어쓰지 않고 ScheduleException으로 표현한다.

## 5. AI 경계

- AI 출력은 JSON Schema 등 기계 검증 가능한 형태여야 한다.
- AI는 데이터베이스 접근 권한이나 메시지 발송 권한을 직접 갖지 않는다.
- 해석 결과에는 intent, 대상 식별자 또는 탐색 조건, 제안 변경값, 확인 필요 여부를 포함한다.
- 신뢰도 저하·검증 실패·모호성은 사용자 확인 또는 추가 질문으로 처리한다.
- 특정 AI 공급자·모델은 제품 요구사항이 아니다. 공급자는 설정으로 선택하고, 같은 도메인 스키마와 검증 규칙을 적용한다.

## 6. 보류된 결정

- 기술 스택과 배포 환경
- 이미지 분석 모델 및 OCR 전략
- 시험 알림의 기본 리드 타임과 반복 정책
- 시간표 데이터 모델을 Course와 CourseSchedule로 분리하는 시점
- Discord에서 확인 UI를 버튼·모달·텍스트 응답 중 무엇으로 제공할지

보류 항목은 구현 편의만으로 확정하지 않는다. 선택 시 `docs/decisions/`에 이유와 영향을 기록한다.
